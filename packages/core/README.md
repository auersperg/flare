# Flare platform — trusted-team preview

Shared Admin + Static Assets and Runtime Workers in the operator's own Cloudflare account, not Workers per application. Online-only Astro/shadcn dashboard, Access, D1 control catalogue/audit, Dynamic Workers, supervisor Durable Objects, persistent native SQLite `app` facets, hibernating live, R2 and Queues/Scheduler.

Application data uses validated documents and native SQLite expression indexes. Queries have no SQL/write capability; mutations, admin edits, revisions and jobs share a transactional path. No ORM, app SQL journal or legacy runtime ABI remains. Only ABI 4 is accepted; use a fresh environment/installation, not an assumed in-place 0.2 upgrade.

Files stream through private R2 grants. Actions use narrow environment capabilities, optional operator-controlled `globalOutbound`, and native Secrets Store bindings. These optional capabilities require provisioning and real-cloud acceptance; no account credential is given to application code. Bounded logical backup/restore to an empty other environment is implemented and cloud-tested. Full analytics, unrestricted/off-account disaster recovery, delegated customer membership remain unfinished. Source 0.3.4 adds portable platform install/status/update; disposable installation/recovery and a genuine 0.3.3 → 0.3.4 upgrade passed in the owner’s account. Independent-account/full-token CLI acceptance and legacy adoption remain separate gates. See [platform lifecycle](../../docs/platform-lifecycle.md).

`bun run verify` checks builds, types, regressions, documentation and external tarball installation. `bun run test:kernel` exercises actual Runtime/SDK code against local workerd, including activation/restore crash checkpoints. Neither command is a cloud deployment, physical cloud hibernation proof or workload/cost certification. Cloud acceptance remains an explicit operator workflow on disposable scopes. Test fixtures stay outside the production package.

API version metadata comes from this package's manifest. The platform workspace is MIT-licensed and npm-private; compiled Core/dashboard assets ship as a CLI-only payload in the single Flare npm archive, not browser SDK exports. See the [canonical architecture](../../docs/architecture.md), [maintenance guide](../../docs/maintenance.md) and [production runbook](../../docs/production-runbook.md). Source entrypoints are `src/admin.ts` and `src/runtime.ts`; the online dashboard lives in `dashboard/`.
