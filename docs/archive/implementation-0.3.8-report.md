## Evidence before publication

- 415 tests, zero failures; source typecheck and Astro diagnostics clean.
- Full portable package acceptance, native kernel/core acceptance and production Admin/Runtime configurations passed.
- Two independent frozen builds produced identical platform digest: `306a5a5e07866fc7c21c88f96c96fa91dcd0ed13ec48599560429f8d1b8c47c3`.
- Accepted archive SHA-256: `25b78c1c7dedbd1ee30f2a4c2b2627a7bd65857679db040f95a844da4e8bba86`.
- Exact 0.3.7 → this 0.3.8 candidate transition passed preservation of data, app release, namespace/resources, Access, signing identity, password session, file and pending job. Its subsequent optional extra recovery drill did not complete; do not label the whole run PASS. Scoped recovery removed all fixture resources and restored the baseline inventory.
- A separate final archive install/features run passed managed configuration, native outbound, cloud push/reconnect/revocation, backup freshness, live status, D1 rediscovery and full cleanup.
- iCloud returned duplicate generated files into `dist`. Verification used a clean isolated Git checkout; payload inventory validation was not weakened. Source/package bytes, not Cloud Drive duplicates, determine the release.

Raw reports, package archives, temporary state and credential-bearing diagnostics stay ignored/private. The earlier failed runs remain evidence, not replaced by invented success.

## Delivery and remaining boundaries

Registry publication and the personal rollout are recorded below only after completion. Existing app code, data, users, files, policies and resource identities are not to be replaced by the platform update.

Real cloud Secrets Store acceptance requires a suitably scoped credential; the current one receives 403. No broader token was silently created. Native binding/protocol execution is verified, but does not prove cloud permission/entitlement.

Backups remain opt-in/on-demand with a manually operated daily objective. Latest completed metadata is not proof of checksum integrity or a guarantee of RPO/RTO. Independent-account install, full graceful drain, off-account recovery and a new load SLA remain outside the verified scope. The failed additional cloud recovery drill is not PASS; native restore/fence/checksum tests passed.

The remaining architectural decisions from the review are intentionally retained: two shared Workers, D1 control plane, isolated Supervisor/facet storage, native RPC, outbox/Queues, table-level reactivity, separate auth boundaries, private streamed files, immutable code releases, one package/lockfile and three canonical guides. No ORM, schema UI, parallel scheduler, telemetry platform or generic RPC framework was introduced.
